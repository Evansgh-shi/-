# 长题库网页、通用错题本与记录迁移

适用于长讲义题库、分组重整、多个课程入口、错题本及已有网页升级。单次聊天出题不要求实现这些网页功能。

## 分清临床专题与选项池

- 推荐层级为“课程—讲义章节—临床/知识专题—同类选项池—分页题组”。章节保留材料追溯；专题按有意义的鉴别、病程、检查或处理关系聚合，不机械按词频分组。
- 不把数百个细小选项池平铺成“章节”。每章展示少量可识别专题；池在专题内下拉切换，提供连练入口。专题多少取决于内容，不能把某一次项目的数量固化为所有讲义的指标。小章可只有一个专题。
- 合并导航不等于合并候选。病名、药物、检查、数值组合等不同字段的池可以归于同一专题，但各池仍独立。只有候选集合、含义及判分逻辑相容时才实际并池。
- 每个有效池恰属一个专题，每题能从其章节及专题到达。增加、移组、退休后重新计算题数、专题数和覆盖引用；打乱顺序校验ID集合，不只比较数组长度。
- 重要的近邻鉴别应形成可发现的专题。若用户说某关系没考到，检查是否真的遗漏、考得不足或被埋在碎组中；不能只找到旧题就拒绝改进，也不要一律再堆同义重复题。
- 多课程沿用一致的层级、题型标记、字号、配色和操作位置，已有课程都保留。不要为统一视觉而抹掉各科必要的来源、图片或分类差异。

## 作答和操作栏

- 沿用用户选择的拖拽交互：选项拖入的是副本，可被多题复用；单题内去重，多选精确匹配且不漏选、不多选。提供先点选项再点答题框及键盘替代操作。
- 默认按单选、多选分区，再在区内打乱；备选答案独立打乱。提交或主动核对前，不通过题名、标签、图注或默认展开的解析暴露答案。
- 专题连练通常保留已有作答；明确的错题重练可以重置所选题当前答案，但需告知范围。切换前后组不能顺手清空；不要把普通切换等同重新组题。
- 在用户已要求固定操作时，让“上一组、提交本组、核对答案、下一组”始终可达，优先复用固定底栏。不同课程、判分状态及滚动位置下保持按钮位置稳定；不用仅出现在长页面末尾的按钮替代。
- 已要求“重做当前题块”时，将其加入同一固定操作栏。重做范围以当前渲染题目ID为准，只清这些题的当前作答、评分并收起解析；保留其他分页/选项池的作答、历史、错题、收藏、旧版归档、题目顺序、筛选、练习清单及当前位置。判分或主动核对后仍可重做；空筛选时禁用，并验证刷新后保留重做结果。不要直接复用会重置整池或仅筛出错题的旧函数。
- 已要求常驻学习位置时，在固定栏或其他常驻区域显示当前课程、章节及必要的专题/部分/分页进度；切组、跨章节、跨科、判分及刷新后同步更新。长名称换行可读，不只放在会滚走的标题或鼠标悬停提示中；预留高度不得挤掉固定按钮。
- 给固定栏预留内容底部空间与手机安全区；选中选项提示、消息、末题、页脚和放大图不能被遮。弹窗应在操作栏上层，关闭按钮和焦点在手机屏幕内；长错题列表可滚动。
- 保留大字与高对比度设计，普通正文对比度以至少4.5:1检查。手机可用紧凑专题下拉替代多行卡片，避免长导航挤走答题区域；不是简单按桌面比例缩小。

## 拖拽反馈与抓取位置

- 需要拖动效果时，浮动副本使用原选项的内容、尺寸和排版；记录按下点在选项内的偏移，移动时保持该点与鼠标或触点对齐。不要改成固定宽度说明卡、额外加偏移，或靠近边缘时突然重心对齐。可用独立裁剪层处理出界，而不是改变抓取点；说明放到目标框或状态提示，不挤大拖影。
- 原选项保留且可复用；高亮有效目标，松手后反馈放入。单选替换，多选追加并去重，重复添加给中性提示，不在拖动或落入时提前判对错。提交后的锁定题不能通过拖动绕过修改限制。
- 鼠标拖动与点选/键盘操作并存。手机可用独立把手或经验证的长按方案，不能为了拖动禁用整条选项文字区的正常滚动。取消、框外释放、丢失触点、切组及关闭页面应清理浮层和高亮；未有效放入不改作答。边缘滚屏避开固定操作栏，减少动态效果设置关闭非必要落入动画。
- 实测拖影与原选项宽高、不同按下位置的抓取点误差及长选项；手机把手拖动和文字滑动分开测试。仅检查浮层出现、目标变色或鼠标中心拖一次，不能证明尺寸和位置正确；模拟事件不等于实际鼠标/触屏拖动。

## 上下组的唯一顺序

- 导航从“章节 → 专题 → 该专题显示的选项池 → 分页”生成显式顺序，并由上下组、首末组恢复及跨科选题入口共同使用。底层题库数组可能交错存放不同专题，不以其相邻索引作为页面顺序，也不为改导航而重编号或重置题目记录。
- 先走完当前池的分页，再到同专题下一部分；当前专题最后部分走完后才进入下一专题。反向切换返回上一部分/专题的最后一页，不回其第一页。仅按当前题型、难度及练习清单跳过确实无可练题的池，不能跳过仍有匹配题的末部分。
- 分别验证普通练习、专题连练、错题/收藏筛选及跨科练习；专题连练清单可能恰好屏蔽其他专题，从而掩盖普通模式中的错序。对完整符合条件的“池ID、页码、题ID”序列做正反向集合和顺序核对，不只比较总题数。
- 必测倒数第二部分到最后部分、最后部分到下一专题、跨专题返回、同池倒数第二页到末页、空筛选和刷新恢复。分页数量覆盖界面支持的常用值及“全部”，题型筛选分别检查单选、多选及全部。

## 通用错题本不等于覆盖课程存档

单课程仍可独立存储；用户要求多课程通用时，在共同入口汇总，不强制增加账号或云端服务。

- 保留各课程原作答命名空间，以 `(courseId, questionId)` 标识汇总条目，避免裸ID碰撞。通用界面可以读取或维护索引，但必须把收藏、移除和重练写回对应课程，不能将一科状态覆盖另一科。
- 提交判分时自动收录该批次答错及未作答题，不能把尚未练习的全库题目都收入错题本。提供单题收藏、一键收藏当前错题、全部错题/未掌握/收藏范围，以及课程、章节、关键词筛选。答对或取消收藏不应自动删掉另一类记录；明确移出错题本后不要在每次加载时再次用历史错误补回。
- 从任一课程入口看到同一批本机错题和收藏。说明存储边界：同一站点/浏览器共享不等于账号云同步；不要声称换设备可自动恢复，`file:`离线页的跨页共享还取决于浏览器策略。
- 直接定位至条目当前所属池，重练应保留必要的读图内容和原来源。旧错选以当时有效的选项文本解释，不将旧池中的同名ID套到新池。
- 收藏或错题写入失败时说明未保存，不把界面变化当成持久化成功。若支持多标签页或导入导出，再核对并发更新及格式校验；不因“通用”自动扩展到多人共享学习数据。

## 跨课程重练

- 保存明确的本次选题清单和课程归属，从源顺序中第一个入选位置开始，不从“最近一道错题”的位置起步而遗漏前面的题。
- 上下组跳过无入选题的池；到课程边界时，在有下一科入选题的前提下继续，允许反向返回；到全部选题终点才禁用按钮。导航到另一科不能恢复成整科所有题。
- 刷新后恢复当前组及作答。用于跨科进入“首组/末组”的一次性参数应被消费，不能让每次刷新都跳回起点。明确退出后安全恢复普通练习，不残留跨科筛选或空白页。
- 测试相同课程、跨课程、仅一题、仅退休题、空筛选、不同题型及末组，不能只测同池两个题的下一步。

## 升级、改写与退休

1. **未改题**：保留稳定ID、选项及当前作答、评分、历史、错题、收藏；移组不应导致整份存档无法加载。仅移组或并池但局部选项ID变化时，按含义映射当前答案、旧错选及顺序；不能按同名局部ID猜映射。无法可靠迁移的题应明确标为受影响项并保留可读归档。
2. **影响作答的改写或改选项**：标记具体变更ID及版本。只重置受影响的当前答案与评分；保留历史和收藏，将旧题干、选项及旧作答归档，必要时标记“题目已更新，待复核”。旧版答对不代表新版已掌握；重新作答后才解除该标记。纯排版或错别字修正若不改变证据、含义与判分，不据此清空答案。
3. **退休或合并**：记录原ID、原因及有效替代ID；有意义的收藏、待练入口可迁到替代题，但不能照搬正确次数或掌握状态。原错选、历史和原答案仍可在可读归档中查看。多次版本的替代链要解析到仍有效的题，排除循环和悬空引用。
4. **练习与顺序**：移除无效ID，修复同长度但内容已变的打乱顺序；仅含退休题的旧练习应转向有效替代或安全退出，而不是永远显示空白。迁移有一次性版本标记，刷新不得重复清空刚做的新版答案。

覆盖清单也要同步改写后的有效题ID；“某条已覆盖”不能指向已删题。保留编辑基线与可复用修订规则，最终构建应用同一套策略，避免重新导入后旧泄题题、旧分组或旧按钮布局复活。

## 验证最终成品

- **数据与内容**：全题ID和来源可解析，答案属于本池，单多选关系正确，专题归属无漏无重、增删后无空池；对新增/改写题逐一核对材料支持及近邻排除。全题自动判分正确仅证明程序与答案表一致，不证明医学结论或干扰项已通过语义审核。
- **关键交互**：拖影尺寸/抓取点与取消清理、选项复用、单选替换、多选精确判分、默认隐藏、主动核对、提交/修改、当前显示题块重做、前后组保留作答、普通/连练模式的末部分与分页往返、图像放大与重置。
- **通用错题本**：从两科各产生记录，验证在任一入口汇总、课程筛选、搜索空结果、跨科收藏/移除、往返重练、末题停用和刷新恢复，不能只测内存中一个课程的对象。
- **迁移**：分别装载有未改题、改写题、退休题、旧错选、收藏和历史的旧存档，验证保留/归档/重置范围及迁移只运行一次；另一课程记录不得被覆盖。
- **桌面与手机**：真实滚动到顶部、中部、底部及判分后，检查常驻章节是否正确、固定按钮坐标、可点击范围、末题是否遮挡、横向溢出、长选项和弹窗关闭。截图须目视复核，模拟DOM断言不能代替实测。
- 验证最终生成并纳入本轮变更的所有课程成品，而不只是统一层之前的中间页面。改了数据或公共运行层后重新构建并执行对应回归；实际浏览器不可用时清楚说明边界，不虚报拖拽或手机实测通过。

## 发布与任务边界

沿用用户已有站点、受众及课程入口，使用环境可用的托管技能和权限流程。技能本身不内置网站地址、项目ID、临时凭证、某次题量或机器路径。用户只要求更新技能时，仅修改技能及其必要资源，不顺带改动或发布网站。
